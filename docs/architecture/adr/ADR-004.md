# ADR-004: Redirect HTTP Status Code

**Status**: Accepted
**Date**: Phase 1

## Context
When a short URL is accessed, the server must redirect to the original URL. Two primary options:
- **HTTP 301 Moved Permanently**: browser caches the redirect; subsequent requests go directly to the target.
- **HTTP 302 Found (Temporary Redirect)**: browser re-requests the short URL every time.

## Decision
**HTTP 302 Found.**

## Rationale
- **Analytics accuracy**: 301 responses are cached by browsers. Once cached, the browser never calls our server again for that short code, making click counting impossible for repeat visitors.
- **Flexibility**: 302 means we can change the destination URL or expire it and the client will always check with us first.
- **Alignment with industry practice**: bit.ly, TinyURL, and other major URL shorteners use 302 for this exact reason.

## Trade-offs
- Slightly higher load on the server (every click hits us vs. cached 301).
- Marginally higher latency for the end user (one extra round-trip to our server).
- These trade-offs are acceptable — analytics accuracy is a core feature requirement.

## Alternatives Rejected
- **301**: Would break analytics after the first visit per browser. Not acceptable.
- **307 Temporary Redirect**: Preserves HTTP method, unnecessary for GET redirects.
